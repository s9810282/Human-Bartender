# 🗄️ L.U.N.A 데이터 구조 안내서 (팀 공유용)

> 작성: 이준서(PD) · 2026-07-23 · 스키마 v2.2 기준
> 이 문서는 "지금 데이터가 어떻게 생겼고, 뭘 고치려면 어디를 만지는가"의 안내서입니다.
> 상세 스키마 정본은 별도 설계서(LUNA_데이터구조_설계서)에 있습니다 — 충돌하면 설계서가 정답.

---

## 1. 큰 그림 — 데이터가 게임이 되기까지

```
① 엑셀 3파일 (사람이 씀)          Document/데이터/
      LUNA_System.xlsx     제조·운영     — 고현정
      LUNA_Narrative.xlsx  대사·서사     — 이준서
      LUNA_Draft.xlsx      대사 초안     — 이기현
            │
            ▼  python3 Document/데이터/tools/build.py  (검사 → 통과해야만 출력)
② JSON 22파일 + 대본 (자동 생성)   Document/데이터/json/
            │
            ▼
③ 게임이 읽음 (웹 프로토타입 → 추후 유니티)
```

- **엑셀이 원본, json은 결과물**입니다. json을 직접 고치면 다음 빌드 때 사라집니다.
- 빌드는 고장난 데이터를 게임에 못 들어가게 막는 문지기입니다. 검사에 걸리면 무엇이 틀렸는지 알려주고 json을 만들지 않습니다.

## 2. 엑셀 3파일 — 누가 무엇을 쓰나

### LUNA_System.xlsx — 게임이 "어떻게 굴러가는가" (고현정, 8시트)

| 고치고 싶은 것 | 시트 |
| --- | --- |
| 칵테일 추가/수정 (가격·도수·태그) | Cocktails + RecipeLines(레시피) |

| 난이도·보상 숫자 전부 | Config + GradeCuts + GradePayout |

### LUNA_Narrative.xlsx — 게임이 "무엇을 이야기하는가" (이준서, 22시트)

| 고치고 싶은 것 | 시트 |
| --- | --- |
| 장면 대사 (누가 순서대로 뭐라고) | Scenes + Steps + Choices |
| 랜덤 손님의 한 마디 | Barks |
| 단골이 언제 방문하는지 | RegularSlots |
| 단골 취향·호감도 보상 | Tastes + AffinityMatrix |
| 단골 수첩 문구 | Dossier |
| 퀘스트 · 엔딩 · 특수 주문 판정 | Quests + QuestStages · Endings · OrderRules |
| 등장인물 · 표정 · SD 동작 | Characters · Expressions · FieldAnims |
| 거리 조사 지점 | Spots(위치) + InteractPoints(지점) |

### LUNA_Draft.xlsx — 대사 초안 원고지 (이기현, 3탭)

| 탭 | 쓰는 것 |
| --- | --- |
| Scenes | 이야기 장면 대화 — "누가, 순서대로, 뭐라고" |
| Barks | 1부 랜덤 손님의 한 마디 — "이런 성격이 이런 상황에 할 법한 말" |
| NPC | 반복 조사 반응 — 시바견·자판기처럼 볼 때마다 반응하는 것 |

- 다 쓴 묶음은 상태를 **전달완료**로 → PD가 스크립트로 Narrative에 가져갑니다.
- 조건·분기·연출 배선은 신경 쓰지 않아도 됩니다 — 지문 칸에 말로 적으면 PD가 처리합니다.
- 각 탭 헤더에 마우스를 올리면 칸별 설명이 뜹니다. INFO 탭에 사용법 전체가 있습니다.

## 3. 표정과 동작 — 장소에 따라 다릅니다

| 장소 | 화면 | 대사에 붙는 것 |
| --- | --- | --- |
| 바 · 집 · 꿈 | 고해상도 흉상 | **표정** (smile, angry …) — Expressions 시트 |
| 거리 (출퇴근길) | SD 픽셀 캐릭터 | **동작** (idle, wave …) — FieldAnims 시트 |

거리엔 흉상이 없으므로 표정을 지정해도 의미가 없습니다. 빌드가 잘못 쓰면 잡아줍니다.
등장인물 자체는 하나입니다 — 삼호는 거리에서도 바에서도 같은 삼호(호감도·생사 공유).

## 4. 배포 JSON 22파일 (자동 생성 — 참고용)

```
게임의 사전     cocktails · shelf_items · characters · expressions · dossier
               cutscenes · field_anims · personalities · barks · tastes · ui_strings
숫자 튜닝       balance (등급컷·배율·호감도표 묶음)
하루 진행       days · random_waves(랜덤 손님) · regular_slots(단골 방문)
               spots · interact_points(거리 조사 지점)
서사            quests · endings · order_rules(특수 주문 판정)
대본            script/bar/dayN.json (바 — 일차별) + home·street·cutscene.json (장소별)
```

## 5. 빌드 검사가 잡아주는 것 (자동)

- **오타 참조** — 존재하지 않는 칵테일·캐릭터·씬을 가리키면 에러
- **선택지 점프(goto) 대상 없음** — 분기가 조용히 끊기는 사고 방지
- **주문할 칵테일이 없는 손님** — 그 시점 해금 티어가 비면 에러
- **손님이 침묵하는 조합** — 성격×상황에 대사가 0줄이면 경고 (카메오 단골 포함)
- **배선 대기 씬** — 초안에서 가져왔지만 아직 연결 안 된 장면 목록
- **영어 누락 집계** — 8월 번역 전까지는 경고만, 한국어로 대체 출력
- 그 외: 조건문(when) 문법 · 플래그 오타 · 호감도 상한 시뮬레이션 · 루나 대사 규칙 등

## 6. 꼭 지켜야 하는 규칙

1. **엑셀이 원본.** json 폴더는 직접 고치지 않는다 (다음 빌드에 사라짐).
2. **(파생) 회색 컬럼은 빌드가 계산한다** — 손으로 고치지 말 것.
3. **id는 영문 소문자+밑줄.** 한 번 정하면 바꾸지 않는다 (다른 시트가 이 값으로 연결됨).
4. **조건(when)에 '또는(OR)'은 없다** — 필요하면 줄을 두 개로.
5. **push 전에 빌드 통과** — 자세한 것은 「기획파트 깃 구조·사용설명서」 참고.

## 7. 궁금할 때

- 각 시트의 **모든 컬럼 헤더에 마우스를 올리면 설명 메모**가 뜹니다 (197개 전 컬럼).
- 각 엑셀의 **INFO 탭**에 그 파일의 사용법 전체가 있습니다.
- 그래도 모르겠으면 지우지 말고 PD에게 — 물어보는 게 지우는 것보다 쌉니다.
