# 스터 기믹 시스템

**정본은 노션 「스터 미니게임」(3b81612298dc809188f0dbd891ecd1e4)** — 이 파일은 초안 보존용이며 콤보 체계 등 옛 내용을 담고 있다.
노션 「스터 미니게임」 하위 페이지 붙여넣기용 완성본. 웹 프로토타입(stir_scene.html)의 확정 동작을 정본으로 기술한다.
붙여넣을 때 §마다 토글 + 구분선 형식으로 나누면 바 내부 시스템 문서와 같은 꼴이 된다.

---

## 1. 개요와 진입

- 스터는 제조 mix 단계의 기믹 중 하나다.
- 진입 조건은 `cocktails.json → mix` 값이 `stir`인 칵테일이다 — 현재 dry_martini 1종(T2).
- 기믹이 끝나면 완성도(0~100%)와 등급을 제조 결과로 넘긴다.
- 기믹 진행 중 바 좌석의 인내심 타이머와 스폰 대기는 전부 정지한다 — 제조 중 정지 공통 규칙.

## 2. 화면 구성

화면은 좌상단에서 우하단으로 내려가는 사선(＼)으로 분할된다.

| 영역 | 위치 | 내용 |
| --- | --- | --- |
| 연출 | 사선 왼쪽 (화면의 30~40%) | 캐릭터가 믹싱 글라스를 젓는 모습. 판정 없음 — 입력 상태를 반영만 한다 |
| 기믹 | 사선 오른쪽 | 탑다운 잔 + 4방위 키 배지 + 바 스푼 시침. 실제 입력·판정 영역 |
| 진행 게이지 | 사선 분할선 위 | 사선과 같은 기울기. 아래에서 위로 차오른다 |
| HUD | 우측 상단 3칸 | 걸린 시간 · 바퀴 n/N · 콤보 |
| 종료 버튼 | 우측 하단 | 목표 바퀴를 다 저으면 활성화 |

### 2.1 연출 영역 (왼쪽)

- 캐릭터는 정면 시점, 얼굴은 하관(턱·입)만 보인다.
- 손은 잔 위 중앙에 고정되고 미세하게만 움직인다 — 손가락으로 스푼을 굴리는 스터 방식.
- 바 스푼은 손 위로도 뻗어 보인다 — 손이 긴 샤프트의 중간을 쥔 형태.
- 스푼 헤드는 잔 바닥 가장자리를 큰 원으로 돈다. 헤드가 왼쪽이면 손잡이 끝은 오른쪽 위로 기우는 지렛대 움직임이 된다.
- 잔 속 얼음 5개가 젓는 속도에 끌려 돌고, 젓지 않으면 서서히 멈춘다.
- 액면 소용돌이는 스푼이 움직이는 동안 진해진다.

### 2.2 기믹 영역 (오른쪽)

- 탑다운 잔: 내부에 얼음 5개와 바 스푼이 보인다.
- 바 스푼은 잔 중심에 피벗을 둔 시침 형태다 — 현재 방위를 가리키고, 정답 입력마다 시계 방향으로 90° 굴러간다.
- 잔 가장자리 4방위에 키 배지: 위 W · 오른쪽 D · 아래 S · 왼쪽 A. 배치는 고정이다.
- 잔 둘레의 링이 바퀴 제한시간 타이머다 — 남은 시간만큼 줄어들고, 34% 미만에서 경고색으로 바뀐다.

### 2.3 키 배지 상태 (4종)

| 상태 | 표시 | 의미 |
| --- | --- | --- |
| 현재 | 보라 채움 + 테두리 | 스푼이 가리키는 방위 |
| 다음 | 청록 테두리 펄스 | 지금 눌러야 하는 키 |
| 정답 | 초록 플래시 | 방금 맞힌 키 |
| 오답 | 빨강 플래시 | 방금 틀린 키. 화면 흔들림 + WRONG 팝 동반 |

### 2.4 진행 게이지

- 게이지는 목표 바퀴 수만큼의 세그먼트로 나뉘고, 세그먼트 사이는 얇은 구분선으로 표시한다.
- 바퀴 하나를 소화할 때마다 세그먼트 하나가 찬다 — 콤보는 금색, 실패는 어두운 적색.
- 게이지가 끝까지 차면(전 바퀴 소화) 종료 버튼이 활성화되고 강조 펄스를 재생한다.

## 3. 조작과 코어 루프

- 입력 수단: WASD 또는 화살표 키. 두 벌 모두 항상 유효하다.
- 기믹 진입 직후는 대기 상태다 — 타이머가 돌지 않는다.
- 스푼은 위(W)에서 시작하고, 시계 방향 다음 키(D)의 정답 입력이 스터 시작 트리거다. 시작 전 다른 방향키는 오답 플래시만 표시하고 소비되지 않는다.
- 한 바퀴 = 시계 방향 4입력. 현재 방위의 시계 방향 이웃 키만 정답이다.
- 정답 입력: 스푼 목표 각도 +90°, 해당 배지 초록 플래시.
- 오답 입력: 그 바퀴를 즉시 실패 처리하고 다음 바퀴로 넘어간다. 스푼은 현재 방위에 남는다.
- 바퀴 제한시간(3.0초)을 소진해도 그 바퀴는 실패다(TIME 팝).
- 바퀴 사이에 쿨다운을 두지 않는다 — 바퀴가 끝난 직후의 입력도 다음 바퀴의 첫 입력으로 즉시 판정한다. 입력을 버리는 구간이 없어야 한다.
- 다음 바퀴의 제한시간은 앞 바퀴가 끝나는 순간부터 흐른다.
- 목표 바퀴를 전부 소화하면 스터가 끝나고 이후 방향키 입력은 무시한다.

## 4. 판정과 등급

- 콤보 = 오답 없이 제한시간 안에 완주한 바퀴. 실패한 바퀴도 목표 바퀴 수를 소비한다.
- 완성도 = 콤보 ÷ 목표 바퀴.
- 종료 버튼을 누르면 등급 화면을 표시한다: 등급 · 완성도 % · 콤보/목표 바퀴 · 걸린 시간.

| 등급 | 완성도 |
| --- | --- |
| PERFECT | 90% 이상 |
| GOOD | 70% 이상 |
| DECENT | 50% 이상 |
| POOR | 30% 이상 |
| SEWAGE | 30% 미만 |

- 예: 목표 10바퀴에서 콤보 9 = 90% = PERFECT, 콤보 7 = 70% = GOOD.
- 등급 경계값은 가안 ❓ — 제조 채점(등급 5종 excellent~sewage)과의 명칭·배점 통합은 「칵테일 제조 시스템」 채점 절 결정에 따른다.

## 5. 연출 수치 (엔진 이식 기준)

- 스푼은 입력에 순간이동하지 않는다 — 목표 각도(target)와 표시 각도(angle)를 분리한다.
- 표시 각도는 매 프레임 `spin × dt × (1 + |남은 각도| ÷ 240)` 속도로 목표를 따라 굴러간다 — 연타로 목표가 멀어질수록 빨리 따라붙어 입력이 밀리지 않는다.
- 좌측 스푼 헤드 궤도: 잔 중심 기준 좌우 ±55(잔 폭 대비 약 70%), 앞뒤 깊이 ±6.
- 손 고정 흔들림: 좌우 ±2.5, 상하 ±1.5.
- 샤프트 손 위 연장 비율: (손 위치 − 헤드 위치)의 0.32배.
- 얼음 끌림: 각속도가 스푼 속도의 0.55배를 향해 수렴하고, 저으지 않으면 감쇠로 멈춘다.
- 바퀴 성공 시 COMBO n 팝(초록), 실패 시 MISS/TIME 팝(빨강) + 화면 흔들림, 전 바퀴 소화 시 FINISH 팝(금색).

## 6. 수치 총괄

| 항목 | 기본값 | 범위(튜닝) |
| --- | --- | --- |
| 목표 바퀴 | 10 | 4~16 |
| 바퀴 제한시간 | 3.0초 | 1.5~5.0초 |
| 스푼 회전 속도 | 340°/s | 150~900 |
| 바퀴당 입력 수 | 4 (고정) | — |
| 얼음 수 | 5 | — |

- 목표 바퀴·제한시간은 `balance.json → stir_rounds`(10) · `stir_lap_sec`(3.0)에서 읽는다 — Config 시트 소속, 전 칵테일 공통.
- 칵테일별 차등이 필요해지면 수동 컬럼이 아니라 tier 파생으로 전환한다 — scoring_items·time_limit 파생과 같은 방식.
- 스푼 회전 속도는 연출값이라 데이터로 빼지 않는다.

## 7. 데이터 연결

- 진입 분기: `cocktails.json → mix` (`stir`).
- mix가 `build`인 칵테일 7종의 젓기 처리 미정 ❓ — 스터 기믹의 짧은 버전(목표 바퀴 축소)을 쓸지, 기믹 없이 통과할지.
- 결과 전달: 완성도(0~1)를 제조 채점의 mix 항목 점수로 넘긴다. 최종 등급 산식은 「칵테일 제조 시스템」 채점 절이 정본이다.

## 8. 필요 리소스 ❗

- 캐릭터 스터 전용 상반신(정면, 하관 노출) — 손 고정 프레임 + 미세 흔들림.
- 믹싱 글라스(측면·탑다운 2종), 바 스푼(측면 긴 샤프트·탑다운 시침형), 얼음.
- 방향키 배지 아이콘 4종 × 상태 4종.
- SFX: 젓는 루프(달그락), 정답 틱, 오답, 바퀴 성공, FINISH. 사운드는 전 항목 미발주 상태의 일부.

## 9. 예외 규칙

- 시작 전 대기 중에는 걸린 시간·바퀴 타이머 모두 흐르지 않는다.
- 바퀴 제한시간 도달과 마지막 정답 입력이 같은 프레임에 겹치면 입력을 우선 처리한다.
- 전 바퀴 실패 시 완성도 0% — SEWAGE.
- 종료 버튼 활성화 이후에는 시간이 더 흘러도 결과에 영향이 없다 — 걸린 시간은 마지막 바퀴 종료 시점에 고정.
- 키 재입력(누르고 있기)은 1회 입력으로만 판정한다.

## 10. 결정 대기 ❓

- 등급 경계값 확정(§4)과 제조 채점 통합 방식(§7).
- mix `build` 칵테일의 처리(§7).
- 오답 시 진행 방식 확정: 현행 = 바퀴 즉시 실패 후 다음 바퀴. 대안 = 같은 바퀴를 재시도(바퀴 소비 없음, 시간만 소모).
