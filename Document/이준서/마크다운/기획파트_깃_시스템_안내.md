## 1. 기획 파트가 레포에 추가하는 것

```
Document/
├─ 데이터/                    ★ 게임 데이터 파이프라인 (아래 상세)
│  ├─ LUNA_System.xlsx        제조·운영 데이터 원본 (고현정)
│  ├─ LUNA_Narrative.xlsx     대사·서사 데이터 원본 (이준서)
│  ├─ LUNA_Draft.xlsx         대사 초안 원고지 (이기현)
│  ├─ json/                   ▶ 자동 생성 — 게임이 읽는 배포 데이터 (22파일 + script/)
│  ├─ tools/                  빌드·초안 스크립트 (파이썬)
│  ├─ 빌드리포트.txt           최근 빌드의 검증 결과 (자동 생성)
│  └─ _archive/               구버전 백업 (삭제 무방)
├─ 고현정/ 이기현/ 이준서/ 임수진/    개인 작업 폴더
└─ (기획 문서 md들)
```

**핵심 구조**: 엑셀이 원본 → `build.py`가 검사 → 통과하면 json 출력 → 게임(웹 프로토, 추후 유니티)이 json을 읽음. **엑셀과 json이 같이 커밋**됩니다 — 엑셀은 diff가 안 보이는 대신, json diff가 "무엇이 바뀌었나"의 기록 역할을 합니다.

## 2. 도구가 하는 일

### build.py — 문지기

`python3 Document/데이터/tools/build.py` 한 줄. 엑셀 2파일(System+Narrative)을 병합해 **60여 가지 검사**를 하고, 전부 통과해야만 json을 내보냅니다. 실패하면 json을 만들지 않고 무엇이 틀렸는지 알려줍니다 → **고장난 데이터는 구조적으로 게임에 못 들어갑니다.**

검사 예시: 존재하지 않는 칵테일/캐릭터/씬 참조(오타), 선택지 점프 대상 없음, 손님이 주문할 칵테일이 없는 날, 대사가 한 줄도 없어 손님이 침묵하는 조합, 조건문 문법 오류, 플래그 오타, 같은 시트가 두 파일에 복사됨…

결과는 `빌드리포트.txt`에 남고, 리포트 상단에 **파일별 시트·행수**가 찍혀 "남의 파일 안 당겨받고 빌드"한 것도 눈으로 걸립니다.

### draft_tools.py — 대사 초안 반영

작가(이기현)가 `LUNA_Draft.xlsx`에 대사만 편하게 쓰면(조건·배선 몰라도 됨), PD가 `import` 명령으로 상태=전달완료인 줄만 Narrative에 가져옵니다. 가져온 장면은 **배선 전엔 게임에서 실행되지 않는 상태(trigger=manual)**로 들어가서, 반쯤 된 초안이 데모에 새는 사고가 없습니다. 같은 걸 두 번 실행해도 중복 반영되지 않습니다.

### gen_luna_data.py — ⚠ 실행 금지

초기 데이터를 코드에서 시트로 뽑아내던 도구입니다. **지금 실행하면 팀이 작업한 시트가 초기값으로 덮입니다.** 실수로 돌렸다면 아무것도 더 하지 말고 git으로 복구(PD 호출).

### 엑셀 자체의 안내 장치

- 모든 시트의 **컬럼 헤더에 마우스를 올리면 설명 메모** (197개 전 컬럼)
- 각 파일 첫 탭(INFO)에 그 파일의 사용법 전체
- 발화자·장소·상태 등은 **드롭다운**이라 오타 원천 차단

## 3. "이러면 어떻게 되나요?" — 상황별 동작

| 상황 | 무슨 일이 일어나나 | 심각도 |
| --- | --- | --- |
| **pull 안 받고 남의 파일과 같은 파일을 수정** | push가 거부되고, pull 받으면 병합 불가 충돌 — **한쪽 수정을 통째로 버려야 함** (엑셀은 부분 병합이 안 됨). 파일 소유자 규칙을 지키면 발생 자체가 없음 | 🔴 유일한 대형 사고 |
| **pull 안 받고 서로 다른 파일을 수정** | push 때 "pull 먼저" 안내 → pull 받으면 자동 병합. **아무것도 잃지 않음** | 🟢 안전 |
| **빌드 안 돌리고 엑셀만 push** | 남들이 받은 json이 구버전(엑셀과 불일치). 다음에 누가 빌드하면 맞춰지지만 그동안 게임엔 옛 데이터가 보임 | 🟡 혼란 |
| **빌드 실패 상태인 걸 무시하고 push** | json은 (실패 시 출력이 안 되므로) 멀쩡한 구버전이 유지됨 — 깨진 데이터가 게임에 가진 않음. 단 엑셀은 깨진 채 공유되므로 다음 사람 빌드에서 같은 에러가 남 | 🟡 민폐 |
| **json 파일을 직접 수정** | 다음 빌드 때 흔적 없이 사라짐. 수정은 반드시 엑셀에서 | 🟡 헛수고 |
| **남의 시트를 참고용으로 내 엑셀 파일에 복사** | 빌드가 "같은 시트가 두 파일에 존재" 에러로 차단 (조용히 섞여 유령 데이터가 되는 사고 방지) | 🟢 자동 차단 |
| **엑셀을 열어둔 채 pull** | pull 자체는 되지만, 열려 있던 구버전을 저장하는 순간 받은 내용을 덮음 → **닫고 pull, 다시 열기** | 🟡 습관 문제 |
| **`~$LUNA_….xlsx` 파일이 보임** | 엑셀이 만드는 임시 락파일. .gitignore가 커밋을 막고 있으니 무시 | 🟢 무해 |
| **gen_luna_data.py 실행** | 전 시트가 초기 데이터로 리셋. git 히스토리로 복구 가능하지만 PD 호출 필수 | 🔴 금지 |

## 4. 다른 파트에 주는 영향

- **기획은 `Document/` 밖을 건드리지 않습니다.** 유니티(HumanBartender/)·아트(ArtResources/)와 충돌 영역이 없습니다.
- 기획은 **공용 브랜치 `plan`**에서만 작업합니다 (개인별 브랜치는 엑셀 병합 불가 문제로 금지). develop에는 직접 커밋하지 않습니다.
- 데이터는 **PD가 빌드 통과를 확인한 뒤 plan → develop 병합**으로 전달됩니다 (금요 통합 빌드 정기 + 요청 시 수시). 기획과 프로그래밍이 만지는 경로가 완전히 분리돼 있어 **이 병합은 항상 무충돌**입니다.
- 따라서 develop이 받는 기획 데이터는 **항상 검증 통과 상태의 묶음**입니다 — 작업 중간의 어중간한 데이터가 develop에 섞이지 않습니다.
- `Document/데이터/json/`은 **추후 유니티가 로드할 데이터**입니다 (연동 시점에 프로그래밍 파트와 스키마 협의 — 사양서는 노션 「데이터 구조 작성」 페이지).
- 커밋량: 데이터 폴더 전체 약 1.6MB (엑셀 3개 + json). 대용량 없음.

## 5. 자주 쓰는 명령 요약

```bash
git pull                                        # 작업 시작 전 (파일 열기 전!)
python3 Document/데이터/tools/build.py           # 데이터 수정 후 검증
python3 Document/데이터/tools/draft_tools.py import   # 초안 반영 (PD만)
git add → commit → push                          # 그날 안에
```
